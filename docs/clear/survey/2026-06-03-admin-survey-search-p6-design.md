# 관리자 설문 검색 조건 강화 P6 설계

작성일: 2026-06-03

## 목표

관리자 `설문 관리`와 `설문 이력 관리` 목록의 검색 조건을 운영자가 실제로 쓰기 편한 형태로 정리한다. 두 화면은 날짜 범위, 상태/사용여부, 검색조건, 검색어를 명확히 유지한다.

검색 파라미터 견고성은 두 종류로 나눠 다룬다.

- `keywordType`, `useYn`, `statuses`는 String/List 타입이라 잘못된 값이 들어와도 예외가 아니라 빈 결과만 발생한다. 이 값들은 500 방지가 아니라 화면 select 표시 정합성과 의도한 조회 조건을 맞추기 위해 허용값 기준으로 정규화한다.
- `startDate`, `endDate`는 `LocalDate` 바인딩 대상이라 잘못된 문자열(`?startDate=abc`)이 들어오면 `BindException`으로 목록 진입이 실패할 수 있다. 이 경우만 실제 500/400 위험원이므로 기본 날짜로 fallback 처리한다.

## 현재 상태

- `설문 관리`는 등록일자, 검색조건, 검색어 UI가 있고 DTO에는 `useYn`도 있지만 화면 필터에는 사용여부 선택이 없다.
- `SASurveyMapper.xml`은 `startDate`, `endDate`, `useYn`, `keyword` 조건을 이미 일부 지원한다.
- `설문 이력 관리`는 제출일자, 상태 복수 체크박스, 검색조건, 검색어 UI가 있다.
- `SAAdminSurveySubmissionController`는 상태 미선택 시 전체 상태를 기본값으로 보정한다.
- 설문 이력 CSV 다운로드는 `normalizeSearch()`를 재사용해 화면 검색 조건과 같은 조건을 사용한다.
- 검색 규칙은 `.cursor/rules/survey-rebuild-project.mdc`의 `Search Rules`를 따른다.

## 선택한 방향

- 설문 관리 검색 조건은 `등록일자`, `사용여부`, `검색조건`, `검색어`로 정리한다.
- 설문 관리의 사용여부 옵션은 `전체`, `사용`, `미사용`으로 둔다.
- 설문 관리 키워드 타입은 규칙대로 `전체`, `설문명`만 제공한다. 현재 검색 대상은 설문 제목뿐이므로 `전체`와 `설문명`은 같은 SQL 조건을 사용한다.
- 설문 이력 검색 조건은 현재 방향을 유지하되 null-safe 보정을 명확히 한다. 설문 이력 `전체` 키워드가 설문명 또는 작성자명으로 동작하는 것은 `SASurveySubmitMapper.xml`에 이미 구현돼 있으므로 신규 작업이 아니라 기존 동작 유지로 본다.
- 설문 이력 상태 옵션은 현재 `신규`, `확인중`, `연락완료`, `처리완료`, `보류`를 유지한다.
- 날짜 기본값은 프로젝트 규칙대로 시작일 `현재일 - 60일`, 종료일 `현재일 + 1일`을 사용한다.
- 날짜 기준은 설문 관리 `등록일`, 설문 이력 `제출일`이다.
- 잘못된 검색 값은 목록 진입 실패로 처리하지 않고 파라미터별로 다음과 같이 정리한다.
  - `keywordType`: 허용값(`전체`, `설문명`, 이력은 추가로 `작성자명`)이 아니면 기본값 `전체`로 보정한다.
  - `useYn`: `Y` 또는 `N`이 아니면 null로 비워 전체 조회로 무시한다.
  - `statuses`: 허용 상태 코드만 남기고 나머지는 제거하며, 비면 전체 상태를 적용한다.
  - `startDate`, `endDate`: 바인딩 실패 시 `SurveySearchRequest`/`SubmissionSearchRequest`의 기본 날짜로 fallback한다.

## 구현 변경

- `SAAdminSurveyController`에 설문 관리 검색 조건 보정 로직을 추가한다.
- `SurveySearchRequest`의 날짜 기본값은 유지하고, 컨트롤러에서 `keywordType`, `useYn`, `keyword`를 화면 표시용으로 정규화한 뒤 정규화된 `useYn`을 model에 추가한다. 현재 `list()`는 `useYn`을 model에 넣지 않으므로 select 바인딩을 위해 추가가 필요하다.
- 날짜 바인딩 실패 fallback은 두 컨트롤러의 `@InitBinder`에 `LocalDate`용 `CustomDateEditor`를 등록해 파싱 실패 시 기본값으로 처리하거나, 동등한 방식으로 잘못된 날짜를 기본값으로 보정한다.
- `admin/survey/list.html` 검색 영역에 사용여부 select를 추가한다.
- `SASurveyMapper.xml`은 기존 `useYn` 조건을 유지하되, 빈 값이나 `전체`는 조건에서 제외되게 한다.
- `SAAdminSurveySubmissionController.normalizeSearch()`는 `keywordType`, `keyword`, `statuses`를 허용값 기준으로 정리한다.
- 설문 이력 CSV는 정규화된 검색 조건을 계속 공유한다.
- 검색 조건 변경은 화면, DTO, mapper의 의미만 맞추고 DB 스키마 변경은 하지 않는다.
- 작업 완료 시 `docs/checklist.md`, `docs/context-notes.md`, `docs/worklog.md`에 P6 구현 결과를 기록한다.

## 화면 설계

### 설문 관리

- 첫 줄은 `등록일자` 기간 검색을 둔다.
- 둘째 줄은 `사용여부`, `검색조건`, `검색어`, `검색`, `초기화`를 둔다.
- 사용여부 옵션은 다음과 같다.
  - `전체`: `useYn`을 비워 조건 없이 조회한다.
  - `사용`: `useYn=Y`로 조회한다.
  - `미사용`: `useYn=N`으로 조회한다.
- 초기화는 `/admin/surveys/list.do`로 이동해 기본 날짜와 전체 조건을 다시 표시한다.

### 설문 이력 관리

- 첫 줄은 `제출일자` 기간 검색을 둔다.
- 둘째 줄은 상태 복수 체크박스를 둔다.
- 셋째 줄은 `검색조건`, `검색어`, `검색`, `초기화`를 둔다.
- 상태를 하나도 선택하지 않으면 전체 상태를 선택한 것과 동일하게 조회한다.
- 검색조건 `전체`는 설문명 또는 작성자명 중 하나라도 일치하면 조회한다.

## 테스트 기준

- 설문 관리 목록 기본 진입 시 날짜 기본값, `keywordType=전체`, `useYn=전체` 표시가 유지된다.
- 설문 관리에서 `useYn=Y` 검색 시 사용 설문만 조회 조건에 포함된다.
- 설문 관리에서 `useYn=N` 검색 시 미사용 설문만 조회 조건에 포함된다.
- 설문 관리에서 잘못된 `keywordType` 또는 `useYn`이 들어와도 목록이 정상 렌더링되고, `keywordType`은 `전체`, `useYn`은 전체로 표시된다.
- 설문 관리/이력에서 잘못된 날짜 문자열이 들어와도 `BindException` 없이 기본 날짜로 목록이 렌더링된다.
- 설문 이력 목록 기본 진입 시 전체 상태가 기본 적용된다.
- 설문 이력에서 일부 상태만 선택하면 해당 상태만 조회 조건에 포함된다.
- 설문 이력 `전체` 키워드 검색은 설문명 또는 작성자명 조건으로 동작한다.
- 설문 이력 CSV 다운로드는 목록과 같은 검색 조건을 사용한다.
- 기존 공개 설문 목록, 설문 작성, 제출, 관리자 상세/미리보기 흐름은 영향받지 않는다.
- `useYn=Y`/`useYn=N` 조회 조건 검증은 컨트롤러가 서비스/mapper에 전달하는 정규화된 `useYn` 값을 assert하는 레벨로 작성한다(SQL 직접 검증이 아님).
- `./gradlew test`가 통과한다.

## 가정

- P6은 기존 검색 UI와 mapper를 보강하는 작업이며 새 목록 API를 만들지 않는다.
- 사용여부 필터는 설문 관리에만 추가한다.
- 설문 이력 상태 코드는 현재 컨트롤러의 상태 옵션을 기준으로 한다.
- 날짜 비교는 현재 mapper와 동일하게 `date(...) >= startDate`, `date(...) <= endDate` 형식을 유지한다.
