# 작업 맥락 요약

## 프로젝트 개요

PHP 기반 설문 접수/관리 사이트입니다.

- 사용자는 공개 화면에서 설문을 선택해 인적사항과 답변을 제출합니다.
- 관리자는 설문 마스터를 등록/수정하고, 사용자가 제출한 설문 이력을 열람합니다.
- 현재 저장소는 JSON 파일 저장 방식입니다.
- 개인정보성 데이터가 담길 수 있는 `data/*.json`은 Git에 올리지 않습니다.

## 프로젝트 규칙 파일

이 저장소는 `AGENTS.md`를 기준 규칙 파일로 사용합니다.

- 용어, 메뉴 구조, 화면 배치, 색상, 검색 규칙 같은 프로젝트 규칙은 `AGENTS.md`에 맞춥니다.
- 레이아웃, 네비게이션, 저장 방식, 동작 방식처럼 눈에 띄는 변경이 생기면 `docs/worklog.md`도 함께 갱신합니다.
- 새 대화방으로 넘어갈 때는 `AGENTS.md`와 이 `worklog`를 함께 보면 현재 상태를 빠르게 복원할 수 있습니다.

## 실행

Docker 기준:

```bash
docker compose up -d
```

접속:

```text
http://localhost:8000/
http://localhost:8000/admin/
```

기본 관리자 계정:

```text
admin
admin123
```

운영 전에는 기본 관리자 계정을 변경하고 `config.php`의 `ADMIN_PASSWORD`도 함께 검토해야 합니다.

## 현재 주요 화면

사용자:

- `/` 접수 가능한 설문 목록
- `/submit.php?form=...` 설문 제출
- `/thanks.php` 제출 완료

관리자:

- `/admin/` 대시보드
- `/admin/management/admins.php` 관리자 관리
- `/admin/management/admin_edit.php` 관리자 등록/수정
- `/admin/management/access_logs.php` 관리자 접속이력
- `/admin/management/change_logs.php` 관리자 수정이력
- `/admin/management/change_log_view.php?id=...` 관리자 수정이력 상세
- `/admin/session/login.php` 관리자 로그인
- `/admin/session/logout.php` 관리자 로그아웃
- `/admin/survey/forms.php` 설문 관리
- `/admin/survey/form_edit.php` 설문 등록
- `/admin/survey/form_edit.php?id=...` 설문 상세/수정
- `/admin/survey/submissions.php` 설문 이력 관리
- `/admin/survey/submission_view.php?id=...` 설문 이력 상세
- `/admin/survey/submissions_export.php` 설문 이력 CSV 다운로드

최근 UI 정리 결과, 설문 등록은 별도 마스터 화면으로 두고 설문 관리와 설문 이력 관리가 각각 목록/상세 역할을 분리해서 담당합니다.
`admin/` 하위는 `management`, `session`, `core`, `survey`로 역할별 폴더를 나눴고, 대시보드는 `admin/index.php`가 담당합니다.
- 기본 `admin` 계정은 슈퍼계정으로 고정하고 관리자 목록에는 노출하지 않습니다.

## 메뉴 구조

GNB:

- 관리자 홈
- 설문 운영
- 사용자 화면
- 로그아웃

LNB:

- 설문 운영
  - 설문 관리
  - 설문 이력 관리

용어 기준:

- 설문 관리: 사용할 설문 마스터를 관리하는 영역입니다.
- 설문 상세: 설문에 사용될 문항, 보기, 사용여부를 제어합니다.
- 설문 이력 관리: 사용자가 제출한 설문을 확인하는 영역입니다.
- 설문 이력 상세: 제출된 설문을 열람만 합니다. 수정 기능은 없습니다.

현재는 관리자 홈, 설문 운영, 사용자 화면, 로그아웃만 GNB에 노출되고, 설문 운영 아래에서만 관련 LNB가 펼쳐집니다.

## UI 규칙

- Bootstrap 5 기반입니다.
- 콘텐츠 영역 배경은 흰색입니다.
- GNB/LNB는 파란 계열로 위계를 둡니다.
  - 1뎁스 GNB가 가장 진함
  - 2뎁스 LNB 그룹이 중간
  - 3뎁스 LNB 메뉴가 가장 연함
- LNB 메뉴 선택 영역은 좌우 끝까지 차야 합니다.
- 목록 제목 앞에는 공통으로 `▶` 마커를 붙입니다.
- 모든 콘텐츠 최상단에는 현재 위치를 표시합니다.
  - 예: `관리자 > 설문 운영 > 설문 관리`
  - 예: `관리자 > 설문 운영 > 설문 이력 상세`
- 카드, 입력창, 드롭다운 등 영역 테두리는 각진 편입니다.
- 버튼과 입력창은 카드보다 조금 더 둥글게 처리합니다.
- 버튼은 내부를 채우는 방식으로 쓰고, 버튼 안 글자는 흰색으로 통일합니다.
- 목록 영역의 기능 버튼은 검색 영역 아래, 목록 상단 우측에 모읍니다.
- 상세/수정 화면에서는 목록 버튼을 좌측 하단, 저장/수정/삭제를 우측 하단에 둡니다.
- 목록 영역의 기능명 왼쪽에는 공통으로 채워진 화살표 느낌의 마커를 둡니다.
- 목록형 영역은 좌우 패딩을 최소화해 표가 가장자리까지 닿는 느낌으로 맞춥니다.
- 탭처럼 보이는 카드형 구조보다는 실제 관리 화면 같은 밀도감을 우선합니다.

## 버튼 색상 규칙

- 등록: 파란색
- 수정: 녹색
- 삭제: 빨간색

상세/수정 페이지 하단 배치:

- 목록 버튼은 좌측 최하단
- 저장/수정/삭제 등 실행 버튼은 우측 최하단

목록 화면의 기능 버튼:

- 검색 영역 아래, 목록 영역 위의 우측 액션 영역에 배치합니다.
- 예: 설문 등록, CSV 다운로드

## 검색 규칙

모든 날짜 입력/표기는 `yyyy-mm-dd` 형식입니다.

기본 날짜 범위:

- 시작일: 현재 날짜 - 60일
- 종료일: 현재 날짜 + 1일

`config.php`에서 `Asia/Seoul` 시간대를 설정합니다.

설문 관리:

- 등록일자 기준 날짜 검색
- 설문 이력과 같은 검색 구조를 사용합니다.
- 검색조건은 전체/설문명
- 전체는 설문명 중심으로 검색 동작을 맞추고 있습니다.

설문 이력 관리:

- 제출일자 기준 날짜 검색
- 검색조건은 전체/설문명/작성자명
- 전체 선택 시 설문명 OR 작성자명으로 검색합니다.

## 목록 컬럼 규칙

설문 관리 목록:

```text
순번 / 설문 제목 / 문항 수 / 사용여부 / 등록일 / 수정일
```

- 별도 상세 버튼은 없습니다.
- 설문 제목을 클릭하면 설문 상세로 이동합니다.
- 설문 제목은 하이퍼링크 효과를 적용합니다.

설문 이력 관리 목록:

```text
순번 / 설문명 / 제출자명 / 연락처 / 상태 / 제출일
```

- 별도 열람 버튼은 없습니다.
- 설문명 또는 제출자명을 클릭하면 설문 이력 상세로 이동합니다.
- 설문명/제출자명은 하이퍼링크 효과를 적용합니다.

## 데이터 저장

현재 설문/이력과 관리자 접속이력은 JSON 파일 저장 방식이고, 관리자 계정과 관리자 수정이력은 MariaDB 저장 방식입니다.

- 설문 마스터: `data/forms.json`
- 설문 제출 이력: `data/submissions.json`
- 관리자 접속이력: `data/admin_access_logs.json`
- 관리자 수정이력: MariaDB `co_adm_mod_mst` / `co_adm_mod_dtl`

주의:

- `data/*.json`은 Git에 올리지 않습니다.
- 추후 운영 단계에서는 MySQL/MariaDB 전환을 고려합니다.

## 최근 작업 메모

- GNB 1뎁스 토글 버튼을 `nav-link` 스타일에서 분리해 한 줄 유지가 되도록 다시 조정했습니다.
- GNB 1뎁스 항목은 본문 링크를 첫 하위 메뉴로 연결하고, 별도 화살표 버튼으로 드롭다운 펼침을 분리했습니다.
- 상세 화면에서도 같은 뎁스의 목록 LNB가 활성 상태로 보이도록 관리자 관리와 설문 관리/설문 이력 관리의 활성 경로를 묶었습니다.
- 관리자 대시보드 카드에는 우하단 방향의 분명한 그림자 판을 추가해 카드가 더 또렷하게 떠 보이도록 조정했습니다.
- 관리자 상세 화면에서는 등록된 계정의 아이디를 수정하지 못하도록 읽기 전용으로 잠갔습니다.
- 관리자 관리 하위에 접속이력과 수정이력을 추가하고, 관리자 생성/수정 시 변경 이력이 남도록 연결했습니다.
- 관리자 화면 진입 시마다 접속 이력을 기록하도록 공용 인증 흐름에 로그를 붙였습니다.
- Docker에 MariaDB 컨테이너를 추가하고 PHP 앱 컨테이너가 MariaDB를 바라보도록 연결했으며, PDO 연결 헬퍼도 준비했습니다.
- MariaDB 호스트 포트를 `3307`로 공개해 HeidiSQL 같은 외부 클라이언트에서 접속할 수 있게 했습니다.
- 관리자 관리 메뉴의 계정 저장소를 JSON에서 MariaDB `co_adm_mst` 테이블로 전환했습니다.
- 기존 `admins` 테이블은 `co_adm_mst`로 옮기거나 정리하도록 저장소 초기화 로직을 맞췄습니다.
- 관리자 테이블은 `adm_seq INT` 키와 `reg_dtm`, `reg_id`, `mod_dtm`, `mod_id` 감사 컬럼만 쓰도록 정리하고, 기존 `created_at`/`updated_at` 컬럼은 제거했습니다.
- 관리자 테이블은 기존 데이터를 비우고 새 `adm_seq INT` 구조로 재생성했습니다.
- 관리자 수정이력은 MariaDB `co_adm_mod_mst` / `co_adm_mod_dtl` 테이블로 만들고, 마스터는 `co_adm_mst`와 FK로 연결했습니다.
- `관리자 관리` 화면을 `관리자 홈`과 `설문 운영` 사이에 추가하고, 관리자 계정 목록/등록/수정과 로그인 계정을 MariaDB로 관리하도록 연결했습니다.
- `admin/`의 기능 페이지는 호환 브리지 대신 `admin/home`, `admin/session`, `admin/core`, `admin/survey` 정식 경로만 사용하도록 정리했습니다.
- 설문 관리와 설문 이력 관리의 검색 영역은 카드 기본 좌우 여백을 유지하고, 목록 표 영역만 좌우 여백 없이 가장자리까지 닿도록 분리했습니다.
- `AGENTS.md`를 프로젝트 규칙 파일로 추가했습니다.
- 화면 상단에는 breadcrumb를 넣고, 각 페이지에는 화면명/기능/생성일 HTML 주석을 남기는 방식으로 정리했습니다.
- GNB는 `설문 운영` 중심으로 재정렬했고, 설문 관리와 설문 이력 관리의 LNB 역할을 분리했습니다.
- 설문 관리와 설문 이력 관리 모두 목록형 화면의 검색/버튼/링크 규칙을 통일했습니다.
- 버튼 색상은 등록 파란색, 수정 초록색, 삭제 빨간색으로 고정했습니다.
- 목록 화면과 상세 화면의 버튼 배치를 좌우 하단 기준으로 맞췄습니다.
- 콘텐츠 배경은 흰색, GNB/LNB는 파란 계열의 위계 색으로 정리했습니다.
- GNB에 `뉴스 > AI News`를 추가하고, `croll/ai-news/*.json`을 MariaDB `co_ai_news_mst`로 올리는 AI News 게시판을 붙였습니다.
- AI News는 목록/상세/등록/수정 화면과 10건 페이징, 검색, 크롤링, 체크박스 다중 삭제, soft delete를 지원합니다.
- AI News 검색은 날짜 범위와 상태 체크박스를 분리해서 쓰고, 상태 검색은 `대기 / 처리중 / 완료 / 에러` 체크박스로 동작합니다.
- AI News 검색 영역은 `날짜 → 상태 체크박스 → 검색바` 순서를 따르고, 상태는 `[기능명] [기능]` 형태로 배치합니다.
- 목록형 검색폼은 날짜, 체크박스, 검색어 모두 `라벨 + 기능` 한 줄 구조로 통일합니다.
- 목록형 검색폼의 입력 폭은 날짜/선택/검색어별로 적당한 고정 폭을 주고, 화면 전체를 과하게 채우지 않도록 조정합니다.
- 목록형 검색폼은 날짜, 체크박스, 검색조건, 검색어, 버튼 영역을 위에서 아래로 줄바꿈해 쌓고, 각 행 내부만 한 줄로 유지합니다.
- 목록형 검색폼에서 검색조건과 검색어는 같은 행에 두고, 하나의 그룹으로 보이게 묶습니다.
- AI News 크롤링은 DB와 JSON 파일 모두 `P` 처리중 상태로 저장하고, 목록/상세의 `게시 확정` 기능으로 `Y` 완료 상태로 바꿉니다.
- AI News 원고는 `tags`와 `sources`를 JSON 문자열 컬럼으로 저장하고, 수동 등록은 `Y` 상태를 기본값으로 둡니다.
- MariaDB 스키마 정의의 관리자/수정이력/AI News 테이블과 컬럼에 한글 `COMMENT`를 추가했습니다.
- 관리자 대시보드에 뉴스 탭 하위 카드인 `AI News`를 노출하고, 대기/처리중 뉴스 우선 및 완료 뉴스 최신순으로 글 상세 링크와 `more` 목록 링크를 제공합니다.
- 관리자 대시보드 카드의 그림자/오프셋 효과를 제거하고 평평한 카드 테두리만 남겼습니다.
- 관리자 메뉴를 MariaDB `co_adm_menu_mst` 기반으로 seed/조회하도록 확장하고, `관리자 관리` 하위에 `메뉴 관리`와 `대시보드 수정`을 추가했습니다.
- 대시보드 현황판 설정은 `co_dashboard_panel_mst`에 저장하며, 게시판형 메뉴를 체크해서 표시 순서와 노출 글 수를 관리합니다.
- `AI News` 대시보드 현황판은 `P(처리중)`과 `Y(완료)` 상태만 대상으로 삼고, `P` 우선/최신순으로 건수와 글 목록을 노출합니다.
